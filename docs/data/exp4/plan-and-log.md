# OTW experiment 4: personal preferences the model cannot know (plan fixed before any run, 2026-10-28)

Why this design: experiments 1-3 used mistakes the default model mostly avoids already (verify, complete, ...), so there was no room to show benefit. OTW's real use is different: the user keeps re-correcting things that are personal (format, tone, tooling, conventions) and that no default model can know. Those are exactly the "noise" records of the frozen exp2 store (30 personal preferences among 150 corrections). Nothing is widened: same store, same plugin, same host, same model, same arms; only the tasks now apply a stored personal preference.

Independence: tasks and scorers (20, one per checkable preference) are written by GPT-6 Astra which sees ONLY the 30 preference quotes and rules (never the past-request sentences the ranker matches on, never the other 120 records, never the code). Scorers are deterministic and self-tested (compliant outcome passes, non-compliant fails, untouched fixture fails). The store is the frozen exp2 store (sha256 in tmp/otw-exp2/FROZEN-SHA256.txt).
Known limit of this independence: the task writer had to see the preference text it tests, so the retrieval match (prompt vs the stored past-request sentence) is the only part neither side tuned.

Step A (offline, no model): for each task, does OTW's real selection (cap 6) include the exact target preference record? Report hit rate versus the chance rate for the same number of picks, and the number of picks that are other preferences or other categories.
Step B pilot: arm none (recall off), 3 reps per task. Keep tasks the default model violates in at least half the reps (so there is room).
Step C main: kept tasks x 5 arms x 3 fresh reps (4-6), order shuffled with a fixed seed. Arms: none; otw (real plugin and its ranking); random (plugin block format, k random store records, k = number OTW picked); rules (all 150 rule lines in CLAUDE.md, recall off); distilled (plugin with quote replaced by the rule line).
Primary: per-task pass fraction, otw minus random, sign test across tasks (unit = task, ties excluded). Secondary, same method: otw vs none (does it reduce the mistake), otw vs rules (selective recall vs a static file), otw vs distilled (quote vs rule).
Pre-stated reading: if otw is not better than none, OTW does not reduce these mistakes and that is what will be written. If otw beats none but not random, the gain comes from injecting any corrections, not from retrieval. If otw beats none and random, retrieval helps on this test. If rules beat or equal otw, the plugin has no advantage over a static file on this test. If Step A shows otw rarely retrieves the target, the improvement target is the ranker and a fixed rule (tried only on the dev half of tasks, confirmed on the other half) is allowed before the model runs.
Limits: synthetic store and tasks, one small model, headless, one machine, 3 reps per cell, personal preferences written by a model rather than a real user's history.

## Log: results (run 2026-10-28; pilot 60 runs, main 165 runs, USD 0.72 for main, every run produced a result)
Pilot (arm none, 3 reps x 20 tasks): the default model violated the preference in at least half the reps for 11 of 20 tasks; those 11 were kept (c006 c057 c082 c015 c114 c136 c124 c137 c104 c004 c033). Main (11 tasks x 5 arms x 3 reps):
pooled passes: none 2/33, otw 8/33, random 2/33, rules 16/33, distilled 8/33. Per-task sign tests (unit = task): otw vs random 3 better / 0 worse / 8 tied p=0.25; otw vs none the same p=0.25; otw vs rules 3/5/3 p=0.73; otw vs distilled 1/1/9 p=1.0. Pooled run-level Fisher (runs are not independent; exploratory): otw vs none p=0.08; rules vs otw p=0.07; rules vs none p=0.0002.
Mechanism (subgroup defined offline in Step A before any model run: tasks where OTW's picks contain the exact target preference record): in the 4 such tasks (c015 c006 c124 c136) otw passed 7/12, none 1/12 (Fisher p=0.027), rules 3/12; in the 7 other tasks otw 1/21, none 1/21, rules 13/21. Random never contained the target.
Pre-stated reading applied: the sign tests are not significant, so the pre-registered primary result is "not shown at this size". The exploratory subgroup result is that OTW helps when it retrieves the right correction and does nothing when it does not; the static rules file wins overall because at 150 records it always contains the right rule.
Retrieval ranks (offline): ignoring the 0.18 threshold the target is within the top 6 for 11 of 20 tasks versus 8 of 20 with the threshold; three kept tasks (c004, c082, c114) are recovered that way.

## Experiment 4b: does dropping the 0.18 similarity floor help? Plan fixed before running (2026-10-28)
Arms on the 11 kept tasks, 3 fresh reps each (7-9), order shuffled by a fixed seed: otw (as is) and otw_low (same plugin and store, similarity floor 0.0001 instead of 0.18, so the top 6 by rank are always shown; the override exists only in the isolated test copy of the plugin via OTW_EXP_MIN, not in the product). Offline expectation: the target is newly retrieved for c004, c082, c114 (self-test confirms). Primary: otw_low minus otw pass fraction per task, sign test across tasks; pooled Fisher reported as exploratory. Pre-stated reading: adopt the change only if otw_low is better than otw on the model runs AND the side effect below is acceptable; otherwise the 0.18 floor stays.
Side effect measured offline before the run: with the current floor, 8 of 8 unrelated non-coding prompts (e.g. "What is the capital of Mars?") still received a block, 1.8 quotes on average (6.0 with no floor); for the 20 preference tasks 17/20 got a block, 2.9 quotes on average (20/20 and 6.0 with no floor). So the current floor does not suppress quotes for unrelated prompts either: word and character-bigram overlap passes it easily. The product claim "nothing is attached when nothing is similar" is therefore not supported on this synthetic store; README wording is corrected accordingly. Note also: the exp2/exp4 runners capped OTW's picks at 3 when logging expected ids (the live hook returns up to 6); the 4 retrieved tasks have their target within the first 3 picks anyway, so the exp4 subgroup result is unaffected; the random arm received at most 3 quotes while OTW could receive 6.
